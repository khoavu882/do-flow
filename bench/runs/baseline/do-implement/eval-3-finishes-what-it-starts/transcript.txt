Implementation
--------------
- bin/doflow.js:
  - Imported `stateRoot` alongside the existing `readLedger` import from `../src/state`.
  - Refactored `cmdStatus`'s context-gathering (registry load, per-harness verification, manifest
    read) out into a new `gatherStatusContext(o)` helper that returns `{ ctx, manifest }`, so
    `cmdStatus` and the new `cmdExport` share one source of truth for "current state" instead of
    duplicating that ~50-line block.
  - Added `cmdExport(o)`:
    - Calls `gatherStatusContext(o)` to build the same snapshot `status --json` prints.
    - Resolves the destination file as `<neutral-state-root>/export.json`, reusing
      `ctx.registry.stateRoot` when the registry loaded cleanly, or recomputing it via
      `stateRoot({scope, projectRoot, homeDir})` (the same rule every other scope-aware command
      uses) as a fallback if the local registry is invalid.
    - `--dry-run`: prints `[DRY] doflow export: would write N bytes to <path>` plus a
      `Dry run complete` line (matching the existing `install --dry-run` / `update --dry-run`
      wording convention) and returns without touching the filesystem.
    - Without `--dry-run`: creates the state directory if needed (`fs.mkdirSync recursive`),
      writes the JSON snapshot to `export.json`, and prints a confirmation line.
    - `--json`: also prints the snapshot to stdout (mirrors `status --json`'s convention).
  - Wired `case 'export': return cmdExport(o);` into the command switch, right after `status`.
  - Updated the `HELP` text: added an `export [path]` line to the Commands section and updated
    the `--json` option's description to mention both `status` and `export`.
  - Deliberately did NOT add `export` to the post-error "some native resources may be partially
    applied" hint list in `main()`'s catch block — export only writes a plain snapshot file, it
    never touches lifecycle-owned/ledger-tracked native resources, so that recovery-record hint
    would be misleading here (matches how `status`/`readiness`/`evidence` are excluded too).

- test/cli-e2e.test.js: added three new e2e tests, modeled directly on the existing
  `install --dry-run previews files and writes nothing` / `status --json emits parseable JSON`
  tests:
  1. `export --dry-run previews the target path and writes nothing` — asserts exit 0, the `[DRY]`
     preview line, and that `export.json` is NOT created.
  2. `export writes a parseable snapshot to <state>/export.json` — asserts exit 0, the file is
     created, and it round-trips as JSON with the expected `manifest.operation` /
     `context.scope` fields.
  3. `export --json also prints the snapshot to stdout` — asserts the JSON snapshot appears on
     stdout in addition to being written to disk.
