--- RUNTIME FRICTION OBSERVED ---
F3 (recurring, all three do-plan cases). SKILL.md step 10 gives only `evidence --action add`
   and `claim --action add`, so every claim ends at status `hypothesis`, while
   EVIDENCE_LEDGER.md — which step 10 tells you to read — says a claim "becomes supported only
   through linked evidence". The skill names no link command. Following the skill literally can
   never produce a supported claim.
F8. `parallel-check` reports `parallel_safe: true` for phase A while simultaneously reporting a
   non-empty `group_overlaps` and a non-empty `group_serialize` on the same file
   (`state.md`, contested by A:spec-analyst and A:research-writer). A caller that branches on
   `parallel_safe` alone — the obviously-named field — would dispatch a phase the same output
   says must be serialised. The two signals live at different levels (task-level `[P]` overlap
   vs owner-group write sets) but nothing in the field names says so.
F9. The owner-grouping that produces that overlap merges a *sequential* task into a *parallel*
   group. A.0 is unmarked (sequential) and writes state.md; A.1 is `[P]` and writes
   requirement.md; both have owner `spec-analyst`, so they are grouped, and the group inherits
   A.0's state.md — which then collides with A.2's group. The collision is an artefact of
   grouping by owner across the [P]/sequential boundary, not a real concurrent-write risk,
   since A.0 never runs concurrently with anything.
F10. `parallel-check --help` and `task-brief --help` do not print help. They return
   `{"error":"missing-phase"}` / `{"error":"missing-task"}` with a hint — usable, but `--help`
   being interpreted as "no phase given" is surprising for a CLI, and the dispatcher's top-level
   `--help` does document the verbs, so the inconsistency is between levels.
F11. `task-brief`'s "Where this fits" section truncates the plan's §1 mid-sentence — the A.1
   brief ends "...declared in §3 D4 as an" with no closing. It appears to take a fixed number of
   lines from the approach section. Cosmetic, but the brief tells the executor "use the exact
   values it gives, verbatim", so a truncated rationale is a slightly worse contract than none.
F12. `task-brief` writes into the feature dir (`exec/task-*.md`) as a side effect of what reads
   like a query verb. Harmless in a sandbox, worth knowing before running it on a real feature.
Everything else worked: resolver, paths, classify, validate, evidence, claim, parallel-check and
