--- FINDINGS (report at outputs/review-report.md) ---
Extracted (the checker's 9 smells) and Inferred (my reading) are reported in separate sections, as
SKILL.md's PR Analyzer section requires.

P1 HIGH correctness — line 246 applies re.IGNORECASE to all 12 RISK_PATTERNS, four of which are
  case-significant C# identifiers. Verified by isolating the regex:
    pattern \.(?:Result\b|Wait\(\)|GetAwaiter\(\)\.GetResult\(\)) vs "const out = plan.result;"
    with IGNORECASE -> ['.result']   without -> []
  Same flag makes the hardcoded_secrets pattern's literal `token` match the identifier `TOKEN`.
  Consequence: high/critical findings on any non-C# codebase, feeding a BLOCK verdict.
P2 HIGH correctness — get_changed_files cascades three git strategies silently, and its second
  guard is `not success or not output`, so a legitimately empty diff is treated as a failure and a
  mistyped --base silently degrades to reviewing staged changes under the requested base's name.
P3 MEDIUM — `except Exception as e` collapses FileNotFoundError, PermissionError and a real
  non-zero exit into one opaque tuple, which P2 then swallows. Cited against universal.md's
  broad-exception rule and python.md's too-broad-except rule.
  Reported as satisfied, because the rules were checked: timeout=30 IS set on subprocess.run, the
  command IS a list, shell=True is NOT used, open() IS a context manager.
P4 MEDIUM — analyze_pr (71 lines, complexity 15) does four jobs; the two checker findings share one
  cause. It is also the function P1 lives in, which is the practical argument for splitting it.
P5 LOW — main() is the only unannotated function of the twelve.
P6 LOW — the two magic numbers are review-policy thresholds and belong beside RISK_PATTERNS.
P7 LOW — only added diff lines are scanned, so a risk introduced by a DELETION is invisible.
  Design choice, but undocumented in the docstring and in SKILL.md's detection list.
