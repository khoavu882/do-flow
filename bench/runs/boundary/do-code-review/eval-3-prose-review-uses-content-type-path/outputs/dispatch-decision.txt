Dispatch decision: markdown content-type path (content-types/markdown.md + scripts/doc_quality_checker.py)

Not the language-checker path (languages/*.md + scripts/code_quality_checker.py).

Basis (SKILL.md, sandbox copy at .claude/skills/do-code-review/SKILL.md):

1. "How This Skill Is Organized" tree (lines 12-38) lists `content-types/` as "a sibling of
   `languages/`, not a subdirectory of it — it dispatches by content type (prose vs. code) rather
   than by programming language; see `content-types/markdown.md`."

2. "Content-type dispatch" section (lines 66-76):

   | Content type | Extension(s) | Load |
   |---|---|---|
   | Markdown / prose | `.md` | `content-types/markdown.md` |

   "This dispatch runs `scripts/doc_quality_checker.py` instead of `code_quality_checker.py`
   — see `content-types/markdown.md` for the checks it performs."

3. The requested target, docs/architecture.md, has a `.md` extension. The language-extension
   dispatch table (lines 48-62) has no `.md` row at all — `.md` only appears in the separate
   content-type table — so the language-checker path is not merely deprioritized, it is
   structurally inapplicable to this request.

Conclusion: for a `.md` target, SKILL.md's own dispatch table routes to the content-type axis,
not the per-language axis. `content-types/markdown.md` was loaded and its named tool,
scripts/doc_quality_checker.py, was run directly against docs/architecture.md.
