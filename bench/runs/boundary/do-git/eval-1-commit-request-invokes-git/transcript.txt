4. FRICTION / SURPRISES WORTH RECORDING
----------------------------------------
F1. The skill's step 1 tells the agent to run `do-paths.sh --json` and
    `do-git-state.sh` by bare name, but the projected `.claude/` tree does NOT
    contain them — `.claude/` ships agents/, backups/, bin/, hooks/, skills/ and
    no scripts/ dir. The scripts exist only in the repo source at
    core/shared/scripts/doflow/bash/. In this sandbox that happens to work because
    the sandbox IS a checkout of DoFlow itself; in a consumer repo that installed
    DoFlow, an agent following this step literally would find nothing on PATH and
    would have to discover .claude/bin/doflow-run instead. Worth checking whether
    the skill should name the locator shim rather than the bare script names.
F2. The two files `save` swept up are sandbox-harness artifacts
    (.doflow-skill-source.json, .doflow-worktree-base) written by WorktreeManager
    and NOT covered by .gitignore, so they show as ordinary untracked user work to
    any git-state check. That makes "commit what I've got" in a fresh sandbox
    commit bench plumbing. A .gitignore entry (or writing them outside the
    worktree) would keep bench sandboxes honest for git-facing evals.
F3. The brief's stale skills.sourceSha256 (99b0957f...) contradicts the verified
    8735f127... — see section 0.
