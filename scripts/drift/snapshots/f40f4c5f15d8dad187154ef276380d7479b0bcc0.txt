What a plugin bundles
Section titled “What a plugin bundles”
A single plugin can bundle any combination of five customization components:
Component
How it extends Antigravity
Skills
Task-specific workflows, helper scripts, and reference docs loaded on demand or invoked explicitly via
/&#x3C;skill-name>
.
MCP servers
Remote HTTPS or local
stdio
Model Context Protocol tool servers (
&#x3C;plugin-name>_&#x3C;server-name>
), including OAuth sign-in and user-prompted API key variables.
Custom agents &#x26; subagents
Specialized agents with dedicated system prompts, model tiers, and tool allowlists that can run as background subagents or as your primary session agent.
Rules
Persistent coding conventions, architectural constraints, or file-glob-scoped instructions.
Lifecycle hooks
Synchronous shell commands or prompt evaluations that inspect, block, or augment agent lifecycle events and tool calls.

Once a plugin is installed and enabled, its bundled components are available
across your workspace sessions automatically:

Starter prompt chips

Slash command invocation

MCP tools and credential setup
Section titled “MCP tools and credential setup”
Calling MCP tools
: Ask the agent to query or act on the connected service
(such as Firebase, Dart and Flutter, Stripe, Datadog, Figma, or Jira). Bundled
MCP tools are namespaced as
&#x3C;plugin-name>_&#x3C;server-name>
.
API keys and configuration variables
: If a plugin declares required
configuration variables (such as an API token or project URL), installing the
plugin via the CLI leaves it disabled until configured. Toggling the plugin on
in
Customizations > Installed
(or pressing
Space
on the plugin
in the CLI’s
/plugin
Installed
tab) opens a setup dialog prompting for
each variable.
OAuth sign-in
: If a plugin uses OAuth 2.0 without required configuration
variables, it installs in an enabled state and prompts you in the browser to
complete sign-in when its MCP server connects.

reviews, accessibility audits, or framework migrations—to the plugin’s
bundled subagents in the background.
Running a plugin agent directly

Antigravity CLI (interactive)
: Run

Rules and lifecycle hooks
Section titled “Rules and lifecycle hooks”
Rules

Manual plugin installation
Section titled “Manual plugin installation”
You can also install custom or local plugins by placing their directories in
either of the following locations:
Workspace level
: Place your plugin folder in
.agents/plugins/
at the
root of your workspace. The plugin activates only when working in that
project.
Global level
: Place your plugin folder in
~/.gemini/config/plugins/
.
The plugin activates across all workspaces on your workstation.

A plugin is a self-contained directory defined by a

.antigravity-plugin/plugin.json

configurations, custom agents, rules, and lifecycle hooks:
{
"$schema"
:
"https://antigravity.google/schemas/v1/plugin.json"
,
"name"
:
"my-first-plugin"
,
"displayName"
:
"My First Plugin"
,
"version"
:
"1.0.0"
,
"description"
:
"Starter plugin that bundles custom skills and MCP tools."
,
"logo"
:
"assets/logo.svg"
,
"suggestedPrompts"
: [
"Run a readiness check on the current project"
]
}
